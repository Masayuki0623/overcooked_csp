# MyAgent パッケージ

このディレクトリには、Overcooked環境におけるAIエージェントの実装が含まれています。主に制約充足問題（CSP）を用いたスケジューリングエージェントと、人間行動予測モジュールで構成されています。

## 1. CSPAgent (Constraint Satisfaction Problem Agent)

`CSPAgent.py` は、Google OR-Tools の CP-SAT ソルバーを使用して、最適なタスクスケジュールを生成するエージェントです。

### 特徴
*   **最適スケジューリング**: 単なるグリーディ（貪欲）法ではなく、全タスクの完了時間（Makespan）を最小化するようなスケジュールを計算します。
*   **並列実行の考慮**: 「鍋で煮込んでいる待ち時間」に「他の食材を切る」といった、リソースの有効活用を考慮した計画を立てます。
*   **環境適応**: 環境の状態（既に切られた食材がある、鍋が使用中など）をリアルタイムに検知し、不要なタスクをスキップして再計画します。

### スケジューリングロジック (`solve_csp_scheduling`)

#### 変数とモデル
*   **タスク**: `chop`（切る）, `cook`（鍋に入れる）, `serve`（配膳する）。
*   **区間変数 (IntervalVar)**: 各タスクの開始時刻、終了時刻、所要時間を表現します。
*   **資源 (Resources)**:
    *   **Agent**: 同時に1つのタスクしか実行できません（`NoOverlap`制約）。
    *   **Cutboard**: 複数のまな板があり、`chop` タスクはいずれか1つを使用します。
    *   **Pot**: 複数の鍋があり、`cook` から `serve` までの間、特定の鍋を占有します。

#### 制約条件 (Constraints)
1.  **順序制約 (Precedence)**:
    *   同一注文内において、`chop` $\to$ `cook` $\to$ `serve` の順序を守る必要があります。
    *   異なる注文間の順序は自由です（並列実行可能）。
2.  **資源制約 (Resource Constraints)**:
    *   エージェントは体が1つしかないため、タスクの実行区間は重複しません。
    *   まな板や鍋も、同時に複数のタスクで使用することはできません。
3.  **調理待機制約 (Cooking Time)**:
    *   `cook` タスク（食材投入）の終了から、`serve` タスク（配膳）の開始まで、**最低150フレーム**（15秒）の待機時間が必要です。
    *   この間、エージェントは拘束されませんが、**鍋は占有**され続けます。

#### 目的関数 (Objective)
*   **Makespanの最小化**: 全てのタスクが完了する時刻（最後のタスクの終了時刻）を最小化します。

### 実行フロー
1.  **タスク生成 (`_build_order_tasks`)**: 現在の注文と環境状態（既存のChopped食材など）から、必要なタスクリストを生成します。
2.  **差分検知**: 前フレームのタスクリストと比較し、増減（例：トマトを切り終わったのでタスク消滅）があれば再計画をトリガーします。
3.  **CSP解決**: OR-Toolsを用いて最適なスケジュール（各タスクの開始・終了時刻、使用リソース）を求めます。
4.  **行動実行**: 生成されたスケジュールに従い、現在の時刻で実行すべきタスクの場所へ移動・対話します。

## 2. HumanPredictor

`HumanPredictor.py` は、人間プレイヤー（パートナー）の次の行動を予測するためのモジュールです。

### 概要
現在の環境状態とエージェントの持ち物・位置から、人間が次に行う可能性が最も高いタスクを推定します。

### 予測ロジック
1.  **状態ベースの即時判定**:
    *   生の食材を持っている $\to$ 「まな板へ移動して切る」
    *   皿を持っている $\to$ 「鍋へ移動して盛り付ける」
2.  **コストベースの判定**:
    *   現在の注文に必要な全タスク（Chop, Cook, Serve）について、人間エージェントの位置からの「移動コスト（距離）」を計算します。
    *   最もコストが低い（近い・手っ取り早い）タスクを予測行動とします。

### コスト計算の詳細
*   **Chop**: `現在地` $\to$ `食材` $\to$ `まな板` の距離。
*   **Cook**: `現在地` $\to$ `食材` $\to$ `鍋` の距離。結合オブジェクト（Merged Object）の中身も再帰的に探索し、必要な食材が含まれているか判定します。
*   **Serve**: `現在地` $\to$ `皿` $\to$ `鍋` $\to$ `配膳口` の距離。

## 3. ファイル構成

*   `CSPAgent.py`: CSPエージェントのメインロジック。
*   `HumanPredictor.py`: 人間行動予測モジュール。
*   `GreedyAgent.py`: 比較用の貪欲法エージェント（単純なルールベース）。
*   `csp/`: CSPソルバー関連のユーティリティ。
    *   `model.py`: OR-Tools `cp_model` のラッパー。
    *   `solver.py`: ソルバー実行関数。

## 4. TaskAgent

`TaskAgent.py` は、特定の単一タスクを実行するためのデバッグ・テスト用エージェントです。「トマトを切る」「スープを作る」といった個別の動作検証に使用します。

### 使用方法
コマンドライン引数 `--task` で実行するタスクを指定します。

```bash
python agent/agent/play_main.py --map ring --agent Task --task <TASK_NAME>
```

### サポートされているタスク

#### 1. Chop Task (`chop_<ingredient>`)
新鮮な食材を取得し、まな板で切り、テーブルに置きます。
*   **形式**: `chop_tomato`, `chop_onion`
*   **動作**:
    1.  `Fresh<Ingredient>` を取得。
    2.  `Cutboard` に置く。
    3.  切る（`CHOPPING_NUM_STEPS` 回インタラクト）。
    4.  `Chopped<Ingredient>` を拾う。
    5.  テーブルに置く（スープ作成のため、他の切った食材があるテーブルを優先）。

#### 2. Cook Task (`cook_<ingredient1>_<ingredient2>_...`)
切った食材を鍋に入れます。
*   **形式**: `cook_tomato_onion`, `cook_onion`, `cook` (自動検出)
*   **動作**:
    1.  環境内にある合わさった切った食材（例: `ChoppedOnion-ChoppedTomato`）を探す。
    2.  それを拾う。
    3.  空いている `Pot` に入れる。

#### 3. Serve Task (`serve_<ingredient1>_<ingredient2>_...`)
調理された料理を皿に盛り付け、配膳します。
*   **形式**: `serve_tomato_onion`, `serve_tomato`
*   **動作**:
    1.  `Plate` を取得。
    2.  指定された料理（例: `CookedOnion-CookedTomato`）が入っている `Pot` へ移動。
    3.  盛り付ける。
    4.  `Delivery` へ運び、提供する。
